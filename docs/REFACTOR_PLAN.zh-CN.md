# AE2 Overclocked 重构设计与发布验收计划

> 更新日期：2026-09-12
>
> 适用平台：Minecraft 1.20.1 + Forge
>
> 状态：结构迁移完成；当前实现与证据见 [REFACTOR_PROGRESS.zh-CN.md](REFACTOR_PROGRESS.zh-CN.md)
>
> 历史：实施前审计基线 `12ee65c`；整理前完整设计稿可从 `e2fd9f3` 的 Git 历史读取

## 1. 目标与完成口径

本轮目标是让并行、超频、大库存与高速 I/O 有明确资源所有权、可恢复状态和有界主线程成本。共享内核与各机器适配已经落地，后续按发现的问题修复，不继续为了结构整齐而扩大改写。

必须区分：

- **结构完成：** 共享规划与执行、批次持久化、long 库存、局部菜单、依赖隔离已经存在并有测试。
- **行为验收：** 在实际依赖、自然调度和客户端路径中确认工作正常。
- **发布验收：** 旧世界迁移、实际客户端、性能、目标整合包和发布构建达到明确标准。

不再用“100% 重构完成”替代后两项，也不以测试总数或工程估计百分比证明没有缺陷。

## 2. 当前架构与边界

| 层 | 当前职责 | 约束 |
|---|---|---|
| `ae2oc/api`、`ae2oc/core` | 资源值、预算、规划、输入事务、不可变批次、执行与统计 | 不依赖 Minecraft/Forge/外部 Mod 类型 |
| `ae2oc/compat/ae2` | 共享平台适配、能量和物品端口、long 存储、持久化编码 | AE2 是当前平台的必选边界，不要求为纸面分层再拆一遍 |
| `compat/extendedae`、`advancedae`、`ae2cs` | 机器配方、流体和外部 API 转换 | 不跨可选附属包共享具体类型 |
| `mixin` | 绑定上游入口、字段与生命周期 | 不新增反射、Unsafe、整段 Overwrite；接管 tick 必须核对上游副作用 |
| `client` | 局部展示槽、权威交互与图标 | 不改变全局 ItemStack 编解码 |
| `migration` | 旧格式解析、只读诊断 | 遇到无法识别的资源不得静默丢弃 |
| 测试源与 `platform/forge` 夹具 | GameTest、核心契约、静态审计、客户端/重启测试 | 发布 Jar 排除测试助手，构建检查裁剪结果 |

`InscriberExport` 和 `ExtendedInscriberExport` 保留两个薄适配器，共享算法在 `SidedExport`；不要为了合并文件引入跨附属类型依赖。

## 3. 资源与批次合同

### 3.1 当前状态模型

`ProcessingState` 保存配方标识、预留输入、待输出、所需/已付能量与剩余推进次数。`BatchProcessor` 负责推进和逐次排出；null 表示没有持有批次。

实际流程：

1. 根据卡片、材料、能量模拟与待输出预算规划次数。
2. 核对输入快照，在服务器线程通过 `SlotTransaction` 预留输入；失败按逆序恢复。
3. 建立并保存批次，此时输入已归批次所有。
4. 逐次记录实际付款；全部付清后推进倒计时。
5. 完成后按预算排出产物，优先网络、再本机允许的落点；每次成功转移后更新剩余账本。
6. 排空后删除批次；重复 load 替换完整状态，不叠加旧状态。

这是当前实现合同，取代实施前设计稿“预留时必须立即付清，否则回滚”的方案。部分付款可以持久化，不应回退成内存中的临时状态。

### 3.2 不可放宽的要求

- 数量非负，数量运算受约束或采用饱和算法；不能用超大真实 ItemStack 作为库存所有者。
- 持有批次时禁止启动第二条上游结算链；卸载、拔卡和菜单动作不能丢失所有权。
- 部分输出成功后再发生错误，先前成功量仍应准确计入。
- 外部端口必须返回真实转移量；抛异常不得伴随不可逆转移。没有端口事务就不能承诺补偿未知副作用。
- 保存和 load 校验遵守现有版本；真实旧世界迁移仍须单独验收。
- 不承诺进程强杀时跨机器/跨区块原子提交；测试要区分正常未保存回档和额外资源异常。

### 3.3 配方适配

配方匹配使用快照投影，扣减按真实差额或配方声明量作用于逻辑端口；不得把投影剩余数量当作完整库存写回。

保留命名压板 NBT、模板不消耗、非对称输入与流体方向等语义。当前附属基线的容器返还/随机多输出模型已经有历史审计，但依赖或数据包变化必须复核。新配方类型应先建立账本测试，再决定是否支持批量聚合。

不要对同类几十个配方机械复制测试；优先不同资源路径、输入比例、NBT、条件加载、流体和第三方修改。

## 4. 库存、降容与破坏

- 受管物品库存以 `AEItemKey + long` 保存数量，给上游库存接口提供合法栈投影。
- 所有权绑定库存实例，不依赖 WeakHashMap/GC。
- 读取历史 Count、ae2ocCount、ae2ocNetCount、旧版 inv（ListTag/CompoundTag）等格式；写入当前规范格式（ae2ocLongSlots，ae2ocDataVersion: 1）。真实世界兼容性已在 Anvil 物理存档四阶段测试闭环。
- 物品/流体超容时保留内容、禁止增加、允许取出。
- 拔掉能源卡截断超过基础容量的能量，不退回网络。
- **按用户定案：破坏机器丢弃罐内与批次流体，仅返回物品。** 正常加工、降容和保存仍要求流体守恒。
- 封存包仅支持物品，图标来自内容物的合法单件副本；历史流体包不兼容。

旧设计“破坏时全部流体打包无损”已被上述明确取舍替代，不再作为待办。

## 5. 菜单与可见状态

### 5.1 已选择的协议

保留 `GenericStack` 包装和 `LogicalMenuSlot/LogicalMenuInteraction/MixinLogicalMenu`。AEBaseMenu 的钩子只路由已明确受管的槽位；其他菜单保留上游路径。

不再计划为了本次收尾引入自定义 VarLong 菜单包，也不恢复全局 FriendlyByteBuf/ItemStack 补丁。

普通取放、合法不同物品交换、Shift 入机受支持。超过单个合法光标容量的旧内容不允许原子交换到光标；数字键/副手、拖拽禁用；滚轮不提供搬运；双击只补充合法光标数量。

### 5.2 当前验证

服务端测试必须观察实际同步回调及原版包编解码结果，不能调用广播后仍直接读取服务器槽位来证明同步。数量、NBT、光标和关闭归还均进入资源账本。

客户端本地包装/解包、图标与独立流体 widget 渲染只是冒烟。当前另有开发期集成客户端 loopback 夹具，使用 AE2 与附属正式菜单 opener/Screen，已覆盖 AE2 压印器 long/NBT 首屏、PICKUP、服务端外部更新、关闭重开与 QUICK_MOVE 守恒；已覆盖 ExtendedAE 4 泳道大数同步与 PICKUP 拾取；已覆盖 AdvancedAE 反应仓容量卡流体 Tooltip（32000 / 2147483647 mB）；已拍摄三机同台世界内 3D 渲染截屏。它仍不替代独立远端服务器的高延迟重连、高频网络丢包容错等远端特有场景。

### 5.3 工作状态

AE2/ExtendedAE 压印器、切片器、反应仓和 AE2CS 的批次付款进度已映射到上游显示字段。进度付清后在倒计时期间保持满格，结束归零；不把它标成时间百分比。

压印器压合标志同时驱动上游产物结算。AE2 与 ExtendedAE 当前实现均不设置服务端 `smash/finalStep`，而是在共享倒计时结束时通过方块实体更新流发送一次性视觉脉冲与单件产物；客户端独立重启动画并由渲染器读取副本。ExtendedAE 在四条泳道 tick 后聚合事件，通过一个全局脉冲和四个泳道产物复用上游动画。load 清除未发送的瞬时事件，快速连续脉冲会重新计时。包往返已测试，但插卡接管、拔卡交回和世界内肉眼效果仍需真实客户端验收。

切片器的上游配方 context 与共享快照分离。当前在上游生成网络字段后使用持有批次的主产物覆盖 `renderOutput`，其 working/progress/产物已通过第二实例解码验证；真实客户端三维观察仍是发布验收项。

## 6. 调度与性能

### 6.1 已有预算

当前配置默认值来自 `Ae2OcConfig`：

| performance 键 | 默认值 | 用途 |
|---|---:|---|
| maxRecipeOperationsPerMachineTick | 4096 | 规划/总线操作预算 |
| maxPendingOutputAmountPerMachine | 1048576 | 批次待输出资源量限制 |
| maxTransferKeysPerMachineTick | 64 | 排出键/调用预算 |
| maxTransferAmountPerMachineTick | 1048576 | 搬运数量预算 |
| blockedRetryMinTicks | 5 | 初始阻塞重试间隔 |
| blockedRetryMaxTicks | 100 | 最大阻塞重试间隔 |

ExtendedAE 四泳道通过 MachineBudget 分片。当前分片最小值为 1，极小配置下四泳道总和可能高于整机配置；正式严格整机上限需在预算边界测试中核对，不能笼统宣称所有参数下严格共享。

已有配方操作预算不等于配方搜索和整网所有调用均被全局限额。先测真实热点，再决定进一步预算化。

### 6.2 时间口径

`cards.overclockCardProcessTicks` 默认 5，但倒计时按处理器调用推进。网格调度间隔、缺能付款、退避和输出堵塞都会影响真实世界 tick 延迟。

受控环境实测（4 超频卡）：条件满足到首批可用稳定为 **4 世界 ticks（约 248~250 ms）**，与 5 次倒计时推进调度吻合。

### 6.3 分级基准与已测基线

基础性能测量套件（`MachinePerformanceBenchmark`）已完成单机与 64 机并发在独立 Dedicated Server 环境下的 8 组隔离场景实测：
- 环境：Windows 11，Java 17.0.20，20 Cores，Max Heap 4002 MB，严格离线。
- 稳态两件并行单机吞吐为 0.40 items/tick（MSPT 均值 1.375 ms），64 机稳态并发吞吐为 25.60 items/tick（MSPT 均值 1.406 ms）；
- 64 机极限 MAX 并行冲刺吞吐达 3,768.32 items/tick（100 ticks 产出 376,832 件），服务端 MSPT 均值仅 2.895 ms（P50 2.850 ms, P95 3.520 ms, P99 4.234 ms），远低于 50.0 ms 世界心跳上限；
- 满输出阻塞状态下阻塞退避有效激活，64 机阻塞 MSPT 均值仅 1.660 ms，避免了无效的配方扫描与状态遍历。
- 完整原始数据固化于 `build/reports/benchmark-results.json`，并通过 `scripts/verify-benchmark.ps1` 自动化复现。

## 7. 兼容与构建

依赖版本、文件 ID 与允许范围集中维护。当前 RC 对 AE2/三个可选附属采用已验证精确版本，见进度文档；没有安装附属时仍可启动，范围外版本由 Forge 拒绝。

`Ae2OcMixinPlugin` 的代表方法检查只是补充防线，不是全签名验证。构建的 `verifyMixinTargets` 检查 compiled Mixin 对 mapped/生产 Jar 的静态目标，并内置空生产索引负向对照。它不保证局部变量捕获和实际运行注入数，GameTest 与客户端仍必需。

每次扩展支持范围：

1. 读取目标 Jar 元数据及传递依赖，不猜 Mod 版本或 JarJar 配套关系。
2. 更新文件 ID、范围、Gradle 锁与 SHA-256 校验。
3. 运行 build/check、五组合以及涉及的客户端、配方与生命周期测试。
4. 发布明确矩阵，不使用无限版本范围暗示未经验证的兼容。

已有 CI 五组合会执行上述构建检查。本轮本地通过不代表远端 CI 或全新缓存已执行。

## 8. 后续批次与发布门槛

| 批次 | 必要性 | 验收内容 |
|---|---|---|
| 客户端行为 | 发布前（代表菜单链路已补） | loopback 已覆盖实际 InscriberScreen 菜单取放/Shift/重开/更新、long/NBT；仍需独立连接/重连、超容与流体提示，肉眼确认 AE2/ExtendedAE 压印器动画和切片器产物 |
| 迁移与构建 | 面向旧用户发布前（迁移已闭环） | 真实旧世界副本账本已通过物理 Anvil 迁移与在途加工守恒闭环；全新缓存、远端 CI、最终 Jar 启动待完成 |
| 基础性能 | 发布前（已闭环） | 单机与 64 机并发在空闲/持续加工/阻塞/Max 并行下的首批延迟、吞吐、MSPT（平均/P50/P95/P99）已完成受控测量并输出 json 与基准表格 |
| 目标共存 | 按支持声明 | Mega Cells/AppFlux/BiggerStacks 等带来的不同资源、协议与 I/O 路径 |
| 扩展压力 | 初步结果之后 | 更多生命周期、异常终止、长时压力与循环，不机械穷举所有组合 |

每批先读当前实现和上游来源，使用能检出缺陷的断言；有意义的负向对照应撤销后复测。修复、测试、文档分别以可审查提交推进。日志/截图留在构建报告，当前状态只维护在进度文档。

## 9. 不在本轮继续扩张的事项

- 不同时迁移 Minecraft 1.21.1/NeoForge。
- 不为减少文件数量破坏 compat 边界。
- 不在没有基准的情况下增加全局调度框架或全面重写状态机。
- 不为显示大数量恢复全局协议补丁。
- 不在真实生产世界直接做首轮迁移试验。
- 不把每个同类配方、每张卡所有笛卡尔组合、100 次重启作为当前修复提交的统一门槛。
