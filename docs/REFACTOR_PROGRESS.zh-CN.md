## 1. 当前结论

核心架构和主要生产适配已经落地，项目已进入重构收口阶段。当前不能直接称为正式发布版，但剩余工作多数是验证、兼容矩阵和性能测量，而不是继续大规模改写生产代码。百分比是基于关闭门槛的工程估计，测试数量只代表已固定场景。

预计再完成 2～4 个独立闭环即可宣布“代码重构完成”；若连同完整发布验收一并关闭，预计还需 6～9 个闭环。外部依赖升级若暴露 API 破坏，实际工作量可能上浮。

- 已有共享处理器、输入预留事务、long 逻辑库存、批次持久化、有界加工/搬运、失败退避与升级缓存。
- 生产源码已清除 `java.lang.reflect`、`sun.misc.Unsafe` 和整段 `@Overwrite`；构建检查限制这些模式及核心/API 包的平台依赖。
- 四台 AE2CS 均有真实配方矩阵、两种能源场景的自然世界 tick 证据，以及本轮两种批次生命周期证据。
- 重构收口只剩 G3 菜单协议；G1（配方投影与 tick 语义）和 G2（生命周期安全）均已关闭。其余配方穷举、性能基准和旧世界矩阵归入发布验收。

### 3.3 自然调度与本轮生命周期的精确范围

自然能源场景只观察世界 tick，不主动调用 `serverTick()`。节点销毁场景先确认 active，再销毁节点；缺能场景确认无能量、不预留、不消耗输入。充能后逐 tick 守恒，400 世界 tick 内完成、无残留批次，并核对实际扣能。

| 机器 | 自然能源场景投入 → 产物 | 精确耗能 |
|---|---|---:|
| 粉碎机 | 8 燧石 → 8 火药 | 64,000 AE |
| 聚合器 | 三路各 64 → 64 逻辑处理器 | 102,400 AE |
| 蚀刻器 | 三路各 8 → 72 逻辑处理器 | 28,800 AE |
| 熵变反应器 | 2 圆石 → 2 石头（HEAT） | 3,200 AE |

本轮生命周期测试统一准备 2 次操作，装并行/能源/容量卡，在世界 tick 自然预留输入并发生付能后中断：

1. **重载+拔卡**：确认批次真实且未完成、全部输入在批次内、尚无产物；对同一保存快照调用两次完整 host `load`，核对批次 NBT（含付款和所有权）不变；拔除并行卡与容量卡，再检查批次不变；自然 tick 完成后核对投入/产出和总耗能。能源卡保留，避免混入既定的拔能源卡截断规则。
2. **真实破坏**：在同样的真实未完成批次上调用 `Level.destroyBlock`，确认方块实体已移除；2 tick 后核算掉落实体中的普通物品和资源包，所有预留输入恰好返回一次，未完成产物为零。

粉碎机生命周期场景为 2 燧石 / 16,000 AE；另三台与上表一致。该组 GameTest 没有覆盖剩余可见输入、输出超容、已完成待输出批次的真实破坏或实际区块卸载；后续 `d3e1162` 已另行覆盖正常停服的跨进程恢复。

## 5. 已定合同与尚未决定的行为

1. **能源与断网已定案**：与上游一致，内部缓冲优先，再尝试网格能源；共享处理器不要求主节点 active，缺能走退避。单独放置机器也可能非 active。网格不是加工前提，但可以供能并作为输出目标。AE2/ExtendedAE/AdvancedAE 由网格 tick 管理器驱动，节点失效可能根本不再被调度；AE2CS 由世界 tick 驱动，四台已有自然证据，不能泛化成所有机器断网都继续 tick。`6035b7f` 进一步固定两条网格驱动证据：无网格/无能量时不消费、不预留，且配方本身可满足；网格与能量到达后自行按自然 tick 完成并足额付费（写真实库存即触达上游 `onChangeInventory` 唤醒路径，夹具不直接调用 tick 管理器或 ticker）。**待优化观察**：装并行卡的机器在空闲（无批次且配方源返回 null）时，自定义路径仍返回 `SLOWER` 而非交回上游的 `SLEEP`，即空闲升级机器会被持续按最大 tick 间隔调度；第 7.2 节允许 `SLOWER`，故本轮未改动，留作后续预算/调度优化项。
2. **有界自动输出**：切片器和反应仓接管后已补回输出；AE2CS 上游四台只写本地槽，没有需要补回的自动输出。`SidedExport` 只处理物品，`ReactionExport` 通过 MEStorage 按接收量扣除；方向/动画/状态仍需逐机复核。
3. **外部端口合同**：必须准确返回实际转移量，抛异常不得伴随不可逆转移。核心不能推断并恢复“先产生副作用再失败”的外部行为。
4. **降容取舍已定案**：物品/流体保留超容数量，禁止继续插入、允许提取；拔能源卡按既定玩法截断超额能量。
5. **破坏流体取舍已定案**：机器破坏时罐内及批次流体丢弃，不生成封存包；正常加工、降容和保存仍要求守恒。
6. **熵变物品掉落已验证**：父类组件负责可见物品掉落，本 Mod 追加批次物品；真实破坏测试确认不丢失、不重复。
7. **菜单交互已部分定案**：继续复用 AE2 GenericStack 展示包装，AEBaseMenu 上保留仅作用于受管槽位的局部钩子。普通取放、合法的不同物品原子交换、Shift 入机与双击收集受支持；不同物品交换若旧内容超过单个合法光标栈则拒绝。数字键/副手交换和拖拽有意禁用；受管展示槽不提供滚轮搬运，因为原版服务端 `ClickType` 没有滚轮意图。真实客户端世界验收及最终协议选择仍待完成，不能表述成完全没有菜单 Mixin。
8. **证据边界**：手动 NBT load 不等于区块卸载；正常停服重启不等于崩溃恢复；自然 GameTest 不等于性能基准；addAdditionalDrops 不等于真实破坏；启动冒烟不等于客户端验收。
9. **AE2CS 状态同步已定案**：共享处理器接管 tick 时由 `AE2CSStateSync` 维持 ACTIVE 方块状态与菜单进度字段；进度映射为批次能量支付比例 0..1000，付清后倒计时期间保持满格（节奏与上游不同，语义一致）。熵变 `ENTROPY_CHANGE_MODE` 切换只影响新批次，已预留批次按原配方完成。其余机器接管后的进度/动画可见差异未排查。

## 8. 接续命令与操作约定

```powershell
$env:JAVA_HOME = 'C:/JAVA/jdk-17'

# 核心契约与架构检查
.\gradlew.bat build --offline

# 严格依赖校验、构建、服务端测试及适配启用断言
powershell.exe -NoProfile -File scripts/verify-compatibility.ps1 -Runtime ae2cs -Offline
powershell.exe -NoProfile -File scripts/verify-compatibility.ps1 -Runtime all -Offline
# Runtime 同样支持 none、extendedae、advancedae

# 全附属客户端启动冒烟（需要图形环境，自动退出）
powershell.exe -NoProfile -File scripts/verify-compatibility.ps1 -Runtime all -Offline -ClientSmoke

# 提交后核对引用与工作区
git log -1 --oneline
git status --short
```

- Windows PowerShell 5.1 的平台检测与原生 stderr 问题已在 d193c10 修复，不再默认要求绕开验证脚本。脚本保留严格依赖校验、退出码、完成标记、测试数量和适配启用检查。
- 近期提交均正常推进分支引用。早期文档曾记载引用写入异常；仅实际复现后才调查 `.git/logs/HEAD` 与分支引用差异，不应常规手工覆盖引用。
- **引用写入异常已复现（2026-09-12）**：本机环境下 `git commit` 能成功写出提交对象与 reflog，但 `.git/refs/heads/` 下的松散引用（含 `refactor/machine-core`，以及实验分支 `a/b/probe`）会在写入后立即消失，`refs/heads/main` 因已打包而幸存；此时 `git status` 会退化成“No commits yet”并把全部文件显示为新暂存。`git update-ref` 同样报成功但不留下文件，因此恢复方式是：从 `.git/logs/HEAD` 末行取出真实提交哈希，直接写入 `.git/refs/heads/<branch>`，随后 `git pack-refs --all --prune` 打包固化。每次提交后应核对 `git log -1`，不一致时按上述步骤修复；不要用 `git reset`/重建仓库这类破坏性手段。
- 每个独立闭环单独提交；不提交本文、设计稿、日志、docs/baseline/，不混入用户原有 `.gitignore` 修改。
- 记录运行时对应的代码与组合，不把历史日志当当前结果，不把附属跳过当功能验证。
- 修复应有负向对照；所有临时故障注入必须撤销，再验证最终代码。
- 复用现有共享组件/导出助手，避免新建重复实现。
- 每次续作后更新本文，但继续保持文档不进入代码提交。
